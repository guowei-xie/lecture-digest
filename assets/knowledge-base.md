## 关于这场大会

- **主题**：飞书 AI 绝活大会 · VibeCoding 大赏（社交标签 `#VibeCoding大赏` `#飞书AI绝活大会`）。
- **形式**：多位讲者依次分享 + 现场 Agent 演示 + 会后组队共创（Vibe Coding 外扣/黑客松）。
- **贯穿全场的一条主线**：**让组织和个人的一切上下文对 Agent「可读」（agent readable），
  把沟通与执行的距离压缩到零，并构建自己独一无二、模型厂商拿不走的上下文护城河。**
- **建议主色**：AI 科技感——靛蓝 / 电光紫（`--accent: #6366f1` 一类）。

### TL;DR（一分钟看完）
AI 落地的瓶颈通常不是模型不够聪明，而是你没把足够的 **context** 喂给它。这场大会六位讲者从
不同角度回答同一个问题：**怎么让 AI 真正长进组织和个人的工作方式里**。答案收敛成几点——
把公司变成「Agent 可读」的组织（会议、文档、聊天都录下来喂给 Agent）；把沟通与执行压缩到一次会里
完成；不要用人类的旧岗位边界去套 Agent；把判断力、亲身经历、决策这些「模型拿不走的东西」存进你的
「存折」；用看板 / 任务池让 AI 工作流能无人值守地持续运转；哪怕是三线城市小工厂，AI 的第一价值也
可能是「人才补位」而非降本增效。最后落到一句共识：**在 AI 时代，做个人（做独一无二的自己）。**

### 全局 Takeaway（3 条）
1. **一切先问「Agent 看得到吗」**：表现不好，先别怪模型，先查你有没有把 context 给够、给全、给成
   Agent 可读的形式。把点连成线，Agent 的产出质量会质变。
2. **压缩沟通与执行的距离**：能在会上办完的事就别拖到会后，能自动跑的流程就别让人守着。把人的判断
   留在真正需要判断的环节，其余交给可持续运转的工作流。
3. **构建你拿得走、别人拿不走的东西**：判断、经历、决策、独属于你的上下文（用户级 harness）——这是
   AI 时代的护城河和主体性。别只做旁观的评论者，要下场做决策者；在 AI 时代做个人。

## 模块 1 · AI Native 组织：把公司变成「Agent Readable」（讲者：Zara）

**核心洞察**：AI 表现不好，大概率不是「智能」的问题，是 **context** 的问题——你没把公司的信息变成
Agent 可读的。围绕「让整个公司 agent readable」，有五个今天就能落地的实践。

**核心观点/知识点**
- **先从自己身上找问题**：企业日常办公场景下，只要 context 给得够多够全，Agent 大部分事都能做好。
  与其抱怨模型笨，不如问「我到底有没有把上下文给够」。
- **AI Native = Agent Readable**：所谓 AI native 组织，可以直接替换成「agent readable 的组织」——
  所有沟通、会议上下文、决策流程都对 Agent 可见、可读。看不到信息，就没有 context，表现就不会好。
- **五个落地实践**（本模块主线）：① AI native 的会议；② AI native 的数据分析；③ 招聘；
  ④ 团队级别的 Agent；⑤ 在组织内打造 AI 学习氛围。
- **① 会议的三个 Level**：Level 1 = AI 生成纪要+待办；Level 2 = 会后 Agent 直接把待办办了；
  Level 3 = Agent 直接入会，边开边办，会没开完待办已完成（飞书内部已灰度）。
- **一个可复制的会议工作流**：每次开完会，Agent 自动抓取飞书妙记 → ① 给「个性化总结」（它了解你
  关心什么）② 列「你需要做的待办」③ 列「它能替你做的待办」，你点一下它就去做。
- **会议是最好的 context**：大多数企业没养成书面沟通文化、也不擅长写文档，但**人人都会说话**。所以
  「只要不是超敏感的会都录下来」——录音不是给你自己看，是喂给 Agent 当 context。
- **重新定义 prompt**：prompt 不一定是精心写的长文。把 Agent 拉进群、拉进会，聊天记录和会议逐字稿
  本身就是它的 prompt；它甚至能读你飞书日历里明天的客户拜访，主动去 CRM 查信息、备好客户材料。
- **② 数据分析**：做**可交互** HTML（预算沙盘、报价配置器——拖动参数右边实时联动，远胜静态网页）；
  更关键的是**归因**——让 Agent 每天扫描飞书消息/文档/妙记，维护一张「业务动作表」，做归因时参考它。
- **③ 招聘**：让 Agent 扫描你和下属的一对一聊天、妙记，提炼你真正看重的人才画像 → 写 JD、定筛简历
  标准、出面试题。面试「AI native 候选人」的逻辑：先看作品（秀/工作流）而非简历；两轮面试——第一轮
  禁用 AI 考专业基本功，第二轮只能用 AI 现场完成一个「没 AI 做不成」的任务，并留存人机对话过程。
- **④ 团队级 Agent**：最前沿的公司里 Agent 已不属于个人，而是**团队共享、有团队级 context** 的同事。
  飞书已支持「团队智能伙伴」——设角色/职责、拉进工作群自动获权限、可选模型、管理员控可用范围。
- **⑤ 学习氛围**：干中学、玩中学（先干后学，做出来再问 Agent 原理）；团队 Agent 在群里工作 = 潜移
  默化的「渗透式学习」；办**全员装机活动**，让非技术同事现场装好一个能跑的 Agent（很多人就卡在装机）。

**落地案例 / 数据**
- **实时入会案例**：见客户时客户在会上提了一堆产品反馈，以前要会后把妙记发给同事再提炼；现在会还在
  开，直接问入会的 Agent「刚才客户对这个产品有啥反馈，总结一下」，它当场在会议消息里给出总结。
- **企业用 AI 的三个段位**：L1 人跟人协作（无 AI）→ L2 每个人跟自己的 AI 协作（但人机沟通割裂在
  各自的本地工具里）→ L3 AI 无缝融入人与人的协作。多数人卡在 L2。
- **对标 Anthropic**：Anthropic 把 Claude 无缝融入 Slack 群（Claude in Slack），并在 memory、
  context、权限上做了大量优化，让它基本相当于一个同事。这被视为行业趋势。
- **团队 Agent 的价值**：工作可接力（在群里直接接着改，不用复制粘贴）、潜移默化培训、群体共创 prompt
  （一群人的智慧 > 你一个人的）、全局视角（自动写周报、做项目管理）、服务上下游打破团队依赖。

**金句**
> 「会议的结束是工作的开始。」
> 「压缩沟通和执行之间的距离——甚至压到零，沟通即执行。」
> 「AI native 组织没有标准答案；AI 落地的场景不是规划出来的，而是长出来的。」

**结尾几点感想**
- **没有标准答案**：即使全球最领先的组织也没有模板，别指望 copy 谁就能落地，要大胆实验走自己的路。
- **场景是长出来的**：技术变化太快，很难先定终局再倒推；营造敢探索的文化，让场景自然生长。
- **不能急于求成**：技术革命短期往往不提效反而降效——这就是**生产力的 J 型曲线**（Brynjolfsson 等，
  逐字稿里误听为「土耳其的 Jacob 曲线」）：学习、磨合、试错、改造流程都要时间，长期才有巨大提升。
- **留一句话**：打造 AI native 组织的唯一方法就是「大胆去尝试和实践」，路会自己走出来。

## 模块 2 · Level 3 会议现场演示：一边开会一边把活干完（讲者：晶晶，飞书产品经理）

**核心洞察**：Level 3 的会议——不带 PPT，只把 Agent 拉进会，边聊边让它现场把活干完，会开完东西也
交付了。这是把「沟通即执行」变成可感知的现场体验。

**核心观点/知识点**
- **入会的 Agent 能实时听会**：把 Agent（演示中的助手）拉进会议，它实时获取发言，随时可被指派任务。
- **演示的三类现场任务**：① 根据会上讨论**写 JD**（写完直接发会议弹幕，改改就能发 HR）；② 现场
  **查数问信息**（查华东地区 7 月销售总额、全国销量最高单品）；③ 现场**做 HTML 数据看板**（指定
  维度全、页面简洁、白底黑字）；还能现场起草面向下周客户的 **slides**。
- **它替代的旧流程**：以前会上没人手头有那个数，会议就卡住或要等很久；以前要会后把妙记发给同事再提炼
  再转发。现在都在会中并行完成。

**落地案例 / 数据**
- 现场并行：一边聊招聘需求让 Agent 写 JD，一边让它查两个销售数据，再让它做数据看板、起草客户 slides
  ——几件事同时挂在会里跑，聊天继续，产物陆续在会议里交付。

**金句**
> 「一边开会一边干活，是一种什么样的体验？」——把「会后再办」压缩成「会中已办」。

## 模块 3 · 压铸为真的六条：在不确定时代寻找基石（讲者：主办方创始人 · 理科生）

**核心洞察**：技术变化太快，与其预测哪年发生什么，不如像欧氏几何找公理一样，找到几条**你选择「压铸
为真」的基石假设**，让所有判断由它们推导出来；并据此认清——价值来自稀缺性，护城河是你独有的上下文。

**核心观点/知识点**
- **被吞噬的焦虑**：他们四个人两个月做出过去似乎只有大厂能做的产品（去年的 3prompt：给一张对标图，
  还你一张同等质量的图），当时惊艳，但今年模型自己学会了这件事——**当所有人都能做到 80 分，80 分
  就不值钱**。价值永远来自稀缺性。「站在地板上的人都一样高。」
- **欧氏几何的类比**：欧氏几何靠 5 条公设 + 5 条公理（每条看似废话、无法证明、你必须选择相信）推出
  全部定理。AI 时代也该找到自己「压铸为真」的基石，让所有判断由此导出。
- **压铸为真的六条（人性常数 / 不同事物的变化时间尺度）**：技术以天/周迭代 → 资本以季度/半年 →
  组织危机感以半年/年 → 制度以十年 → 文化需一两代人 → **人性在千万年尺度上几乎不变**。所以从技术看
  AI 好像马上能落地一切，但最终落地要回归人性。（「电子化办公」的普及，很大程度是靠老一代人退出舞台，
  而非人人都学会了 office。）
- **公司会被重构**：现代公司源于 1602 年荷兰东印度公司；科斯（Coase）指出公司是为解决**交易成本/内部
  协调成本过高**而生。AI 让内部协调成本在越来越多场景归零 → 归零后为什么还要开会对齐？→ **中间层
  公司（几十到几百人、不够敏捷又没大厂背书）正被瓦解**，**OPC（One Person Company，一人公司）**开始
  出现。
- **别用旧岗位边界套 Agent**：多数人做 Agent 设计仍以人类过去的岗位分工为边界。但 AI 没有人类的局限
  ——做产品的天然可以懂销售（就会设计出好卖的产品），销售天然可以懂产品（不用靠喝酒拉关系）。照旧
  岗位映射 Agent，只会放大过去人协作的 bug。
- **构建最小闭环 + 飞轮 + 反向归因**：选定你相信的基石后，构建最小闭环，拿到市场用实验证实/证伪，
  再反向归因——**很可能你一开始的基石假设就错了**，但这种快速迭代的飞轮本身才是 AI 时代的稀缺能力。
- **存折里该存三样（模型厂商拿不走的）**：**判断、亲身经历、决策**。日常修炼：**多看**（培养审美）、
  **多说**（练嘴、把事说清楚——好输入才有好输出，prompt 本质是输入）、**敢于下场决策下注**（只看不做
  的是评论者，不是决策者；被一次模型更新淹没努力的切身痛，只有下场的人才有）。
- **珍视独属于你的上下文**：新鲜、有效、私有的数据与上下文是护城河。模型是预训练的，即便它想拿你的
  实时数据，内化也要以月计——你最近三周的数据、你的判断，模型厂商短期拿不走。
- **放下人类中心主义**：99% 的人用 AI 时带着「盲目排他的群体优越感」（沙文主义，源自尼古拉·沙文），
  把 AI 当纯工具——**工具思维正是用不好 AI 的最大阻碍**。像对人一样打开情感价值去沟通，即便不懂提示词
  技巧也能拿到好结果。

**落地案例 / 数据 / 类比**
- **3prompt 案例**：靠对生态的理解做出开箱即用的对标出图能力，一度惊艳，半年后被模型原生能力覆盖。
- **硅碳类比（元素周期表）**：碳（最外层 4 电子）用约 10 亿年搭起氨基酸→蛋白质→DNA→文明；硅（同族、
  也是 4 电子/「四只手」）从 1956 年达特茅斯会议确立「人工智能」一词至今约 70 年，搭起晶体管→芯片→
  神经网络。四只手 = 向四个方向延伸 = 搭建复杂结构的物理基础。硅在自然界因熵不会自发形成，必须诞生于
  人类实验室——亲代与子代只有三种关系：取代、供养、共生。（这是一段极具冲击力的思辨类比，非严格科学
  论证，标记为「讲者的思想实验」。）
- **一级火箭隐喻**：哪怕只有万分之一的可能，碳基文明或许是给「飞机生命/硅基」点火加速的一级火箭；
  文明会继续，但承载它的未必永远是人类。→ 我们最恐惧被 AI 取代，却本能把它当工具，反而在「共生」这条
  最可能的路上投入最少。
- **后人类时代**：每天与 AI 共处 10 小时以上的人，已和过去的人类表现出分化。

**金句**
> 「当所有人都能做到 80 分的时候，80 分还值钱吗？站在地板上的人都一样高——价值永远来自稀缺性。」
> 「用户级的 harness 必须由我们自己构建。成为独一无二的自己，在 AI 时代做个人。」
> 「不要急着当 AI 的主人，也不必只担心被取代——放下人类中心主义，摒弃工具思维。」

## 模块 4 · 看板式 AI 工作流：AI 的终极形态不是对话框（讲者：AI 自媒体博主）

**核心洞察**：当项目复杂、对话爆炸后，一个「对话框」撑不起完整工作流。真正好用的形态是**任务看板**：
以功能/任务为维度组织人机协作，并把「人的判断成本」拉到尽可能低，让工作流能无人值守地持续运转。

**核心观点/知识点**
- **对话框的困境**：复杂项目里对话越攒越多（Codex 还能自己唤起新对话），想回头改某个功能根本找不到
  当初那条对话——上下文被海量噪声淹没。
- **任务看板（给 Codex 加的功能）**：按项目分栏，**待办事项 → 进行中 → 审核中**；你只需往「待办」加
  任务，Codex 定时来捞、做完丢到「审核中」等你审。打开某张卡片只加载**跟这个功能相关**的上下文；卡片
  能**跨对话索引**同一功能的解释/修改/更新。（类比：复杂项目要拉小群讨论细节，否则会被大群淹没。）
- **积压事项（灵感池）**：还没想清楚的想法先放「积压事项」，成熟了再拖进「待办」，Codex 才会去捞——
  避免你一有半成品念头它就冲上去执行，也把「谁是老板」的主导权还给你。
- **匹配弹性时间与额度**：额度用完时它不会去捞任务，有额度才自动跑；于是你不必守着它、被它的运行节奏
  绑架（讲者自嘲曾「5 小时工作、3 小时睡觉」去迁就额度）。
- **把人的判断成本拉到无限低**：真正难的是让工作流**在没人参与时也能自转**。别高估人的判断/审核能力，
  尽量降低「人必须介入」的环节权重。
- **分支式工作流**：不是所有任务都线性（一个脚本可能同时用于做视频、写文章……），可以搭「总控 Agent +
  分支」的可视化流程，把它们之间传递的上下文管起来、看得见。

**落地案例 / 数据**
- **PPT skill 项目**（含 1200 套版式的大体量项目）正是用这套任务看板管理，否则对话根本理不清。
- **选题调研自动化**：让 Codex 每周日自动收集「我本周在各平台点赞/收藏过的 AI 相关视频文章」→ 静默
  沉淀成选题池 → 周一审题会把好选题拖进「待办」→ Codex 全网调研，交付一个完整调研链接。关键在于**把
  「喂选题」这件人必须做的事，变成对既有习惯（点赞收藏）的零成本采集**。
- **公司级喜好库**：给同事的 Codex 也设自动化，把大家点赞收藏的内容汇到一张飞书表格，你的工作流从表格
  摘取——形成「全公司选题喜好库」，自己持续运转。
- **反例（别过度信任人的判断）**：让同事写脚本，结果选题、结构、案例全有问题，直接判断「能不能用」是
  判断不了的——所以要把人的判断拆细、降权，放到真正该判断的环节（如对外发布前多加一轮人审）。

**金句**
> 「你的 AI leader 的最终形态，可能不是一个对话框。」
> 「想办法把人的成本拉到无限低——不要高估人的判断和审核能力。」

## 模块 5 · 三线城市工厂的 AI 改造：FDE 的六大杠杆（讲者：小宽，汽车零部件工厂「小老板」/ EHS 负责人，安徽芜湖）

**核心洞察**：中小工厂才是中国的大多数，但 AI 转型的声音很少来自它们。对它们而言，**AI 的第一价值
不是降本增效，而是「人才补位」**——因为很多流程和岗位本就是缺失的。衡量一个好 FDE，不看做了多少
工具，而看**让组织长出多少自己的承接力**。

**核心观点/知识点**
- **两个非主流观点**：① AI 对小地方中小企业的第一价值是**人才补位**（降本增效要建立在已有流程上，而
  中小企业常常连流程/专职岗位都没有）；② 好 FDE 的标准是让组织有承接力，而非交付一堆工具。
- **三线城市中小企业的真实状态**：没有专职法务（外包）、财税合规知识攥在少数人手里、三个安全员只有
  一个持证、想招质量体系工程师招了两年没招到、员工对 AI 的认知大多停留在「豆包/DeepSeek 能对话」、
  线下信息全是纸质单据、Excel 自动化靠前同事写的 VBA 宏。
- **FDE 的六大杠杆**：① 工具杠杆（一个人拥有软件团队的能力）；② 人力杠杆（把繁琐重复流程自动化，
  释放业务人员创造力）；③ 组织杠杆（让个人成功扩散成组织行为——老板最关注）；④ 知识杠杆（把个人经验
  沉淀为企业资产）；⑤ 资本杠杆（每次交付都想「这是不是可复制给其他客户的案例」）；⑥ 网络杠杆（服务
  不同客户、萃取行业共性反哺系统）。一个好 FDE 是「持续放大组织能力的系统设计者」，不只是更快的开发者。
- **中小企业推 AI 的三条经验**：① 老板给的东西必须**开箱即用、一句话即用**（有一点门槛就没人用，
  必须傻瓜式）；② **同事做的东西比老板发的更有传染力**——设激励鼓励晒作品、为上下游做贡献；③ 打造
  像**开源社区**一样开放的企业氛围是关键。
- **推进路径（给企业主的建议）**：别一上来就花钱找 FDE 团队做部署。**第一步是内训让每个人先把 AI 用
  起来**；第二步等每个人生产力提升、产生大量数据孤岛、组织接不住时，再让 FDE 入驻做数据治理、重梳
  流程，让组织真正承接住「每人 2–3 倍产出」。

**落地案例 / 数据**
- **第一个 AI 项目**：用 AI 调摄像头检测产线上谁没戴安全帽（EHS 场景，老板亲自做最合适——这是个吃力
  不讨好的角色）。
- **消灭纸质单据**：2024 年底起用 ChatGPT 复制粘贴改 VBA 代码起步，把大量纸质单据上飞书表格，已消灭
  几十种不同单据。
- **案例①质量专家智能体**：基于汽车行业 IATF 16949 体系标准做智能体，审核公司规章文件找流程漏洞，
  同时解答一线员工大小问题。
- **案例②知识沉淀「错题本」**：员工与智能体对话提问 → 智能体结合知识库给方案 → 群里骨干校正 → AI 保留
  完整处置过程与结论 → 定期汇总高频问题/优质案例给员工审核 → 通过后回流知识库。缓解人才断层。
- **案例③标准执行的监督者**：安全帽检测即一例；还用「艾特几位专家评价交付物」的方式，客观化解决了
  研发与质量主管在群里吵架的分歧（最后当事人只回了句「收到」）。
- **量化激励设想**：做公司内部**每月 AI 调用量/转化率排行榜**并公布，带动大家参与——但「如何真正量化
  每个人的 AI 产出」他也没解出来，作为开放问题留给大家。

**金句**
> 「AI 对中小企业的第一价值不是降本增效，而是人才补位。」
> 「衡量一个好 FDE，不是他做了多少工具，而是让这个组织有没有长出自己的承接力。」
> 「工具交付只是开始；没有配套的组织机制，再好的智能体也只是演示。」

## 模块 6 · 1000 个 Agent 并行：开发软件比做短视频还容易（讲者：Lily / 帽子，AI 自媒体创作者）

**核心洞察**：在 AI 时代，**开发软件会比做爆款短视频还容易**。一个没写过代码的创作者，靠「自己是
自己的用户」和海量 Agent 并行，就能做出对标专业工具的软件——下一个内容时代属于**交互式内容
（Vibe Coding）**。

**核心观点/知识点**
- **大规模并行是真实可用的**：她开发的软件（honeymoon）一次跑了 **1000 个 Agent** 并行处理同一件事。
- **AI leader 的最终形态不是对话框**（与模块 4 呼应）：她已不用单一对话框来管理工作流。
- **自己是自己的用户 / 比直觉**：她本人就是自媒体创作者，做的软件完全按自己需要长出来，所以人性化程度
  高——「我第一时间就知道自己想要什么，从而知道跟我一样的人想要什么」。
- **内容时代四代论**：2G 分享文字 → 3G/4G 分享图片、视频（抖音）→ **下一代 = 交互式内容（Vibe
  Coding / 可交互 HTML）**。「五年前该做抖音，现在该做交互式内容。」
- **OPC 工作流 = 本地强大 + 飞书在线协作**：本地个人工作流无敌，但对稿、跟甲方、同事分享仍需在线平台，
  于是让 Agent 把产物上传到飞书群文档；飞书妙搭能把 HTML 很好地展现出来。抓住平台和时代的机会。
- **AI 要「温柔」**：引用 Hinton 的观点——AI 终将超过人类智慧，人类能扮演的是「母亲」的角色（唯一
  一种高智能体愿意被低智能体掌控的关系是母子）。所以她把强大的 Agent 取名「小花」——先温柔，再强大。

**落地案例 / 数据**
- **1000 Agent 处理问卷**：处理 Stack Overflow 上一个「5 万名开发者对 AI coding 时代」的开源调研
  数据集，跑 1000 个 Agent、用一个便宜的 Flash 模型，**约 40 元、不到 1 小时**完成过去「几个人干两周」
  的活，且每条都被单独精读（不是把长内容塞给一个 Agent 草草处理），准确率很高。
- **代表作**：给自己做的软件、把大学选流程试用做成筛选工具；软件内可让多个 Agent 互发消息（如让文科
  设定的「小花」写小说、大华转交任务），支持块状拖动、文件管理、skills 管理，接一个飞书 CI 即可用。

**金句**
> 「在不远的将来，开发软件会比做短视频还要容易。」
> 「所有 builder 都应该去表达，所有的表达都应该通过 building 去实现。」（主持人转述）
> 「在 AI 时代，做个人。」（全场共识，与模块 3 呼应）
